# AI-GAME 愿景

> 当前处于干净、可控的产品基线，没有自动推进的实施阶段。本文只描述长期产品方向。

> 跨仓产品关系见 `D:\AIProjects\WeftMate\Repository\docs\AI-GAME-AUTONOMOUS-MOBILE-TASKS.md`。

> 通用能力的首个代表性 black-box acceptance（黑盒验收）见 `docs/product/ACCEPTANCE.md`。Soul 在该文档中只是第三方 Android 测试环境，不是产品方向或专用实现。

AI-GAME 不是一个独立聊天产品。它是 WeftMate 通过 DeepSeek Harness（执行智能体运行时）调用的长期手机任务子系统。

最终用户关系只有一条：用户在 WeftMate 里直接与 Harness 对话；Harness 理解意图、维护对话和权限裁决；AI-GAME 负责在用户选择的 Android 模拟器上长期执行、验证、等待、恢复、接收任务修改并总结执行经验。

## 最终产品关系

```text
用户
  <-> WeftMate Product UI（产品界面）
  <-> WeftMate Gateway / Runtime Adapter（网关 / 运行时适配层）
  <-> DeepSeek Harness
        |
        | tool call（工具调用）
        v
      AI-GAME 长期手机任务服务
        <-> Android 模拟器适配层
        <-> 用户选择的 Android 模拟器
```

- **WeftMate** 是唯一面向用户的产品入口，承载聊天、工作区、设置和结果呈现。
- **Harness** 是对话与智能体运行时，负责理解用户、规划、选择工具、维护会话，并把执行结果解释给用户。
- **AI-GAME** 是手机任务、设备、动作、事件、证据和任务经验的权威，负责持久任务、时间/事件唤醒、局部计划、观察、动作、验证、等待、恢复、重新规划和运行中修改。
- **MemoWeft** 负责个人长期记忆。AI-GAME 只保存完成执行所必需的作业状态、幂等信息和证据，不建立第二份用户记忆。

用户不需要打开 AI-GAME 控制台，也不需要在 AI-GAME 中建立另一段用户会话。AI-GAME 可以在一个长期手机任务内维护对象、聊天或其他子任务状态；自带控制台仍只服务开发、设备配置和运行诊断。

目标交互从一句自然语言结果开始。Harness 可以在原对话中追问到信息充分，形成用户可读、可修改的任务单；AI-GAME 随后持久执行并从经过验证的动作与恢复结果中形成有范围经验。第二次相似任务只有在实际检索并使用兼容经验、减少重复提问或失败路径时，才算发生了学习。

## 一个手机任务

```text
Harness 判断需要操作手机
-> 发起带唯一调用标识的任务请求
-> AI-GAME 绑定用户选择的模拟器并持久保存任务
-> 按时间或事件唤醒，观察、规划、执行和验证
-> 普通错误进入恢复、等待或重新规划
-> 用户可在原 WeftMate 会话中修改、暂停、继续、插队、接管或停止
-> AI-GAME 持续返回结构化状态、事件、结果和证据
-> 任务按用户结束条件完成后，Harness 在原 WeftMate 会话中给出最终说明
```

AI-GAME 可以为手机任务维护局部计划、时间窗、对象/会话子任务、恢复点、等待条件和执行经验，但不负责通用闲聊、人格、手机领域之外的跨工具总规划或最终自然语言回复。需要用户补充信息时，AI-GAME 返回结构化问题，由 Harness 在原会话中询问；不能再建立一套独立的用户问答界面作为正式产品。

普通页面变化、点错、App 退出、网络波动、对方未回复或一次模型解析失败不应直接结束顶层任务。系统应等待、恢复、重新观察或换方案，并把原因如实投影给 WeftMate。只有用户停止、达到结束条件、确认完成、替代方案耗尽后的真实不可继续，或出现重复副作用、身份串线、凭据暴露、伪造成功等完整性问题时，任务才终止或立即阻断。

## 执行完整性

以下是手机执行服务必须成立的技术事实：

- 用户最新指令、任务 revision（修订）和停止意图由 Harness 传入后必须优先生效；
- 一个物理设备同一时刻只有一个写入者；
- 动作前确认当前设备与新鲜观察，动作后重新观察；
- 接受了工具请求不等于用户目标已经完成；
- 无法确定物理动作结果时先核对，不重复盲发；
- 同一任务、子任务、动作和 tool call 重试时依靠稳定身份与 idempotency key（幂等键）避免重复执行；
- 返回给 Harness 的完成状态必须有可追溯的设备证据支持。

## 本地优先

设备状态、截图、动作记录、恢复点、运行证据和手机任务经验默认留在本机。AI-GAME 不把外部模型响应当作设备结果，也不绕过本地观察和验证。WeftMate、Harness 与 MemoWeft 各自的数据职责由它们的仓库定义，AI-GAME 不复制其用户会话或个人世界。

后续开发、验证和 dogfood（亲自试用）只使用 Android 模拟器。

## 产品排除项

- AI-GAME 自己的普通用户聊天入口、人格或独立产品工作台；
- 与 Harness 重复的通用用户会话、手机领域之外的跨工具规划和最终回复能力；
- 与 MemoWeft 重复的个人长期记忆；
- 让用户直接处理 AI-GAME 内部 Goal（目标）、Profile（能力配置）或运行模式；这些能力应由 WeftMate 以产品语言管理；
- 为某个 App 建立专用顶层产品、固定成功脚本或第二套控制面；
- 阶段流水、Work Order（工单）、固定验收报告、代理任务卡和项目治理控制面；
- 从已删除文档、历史记录或旧实现反推当前需求。

项目是否继续做一件事，只看它是否让“用户在 WeftMate 中与 Harness 对话，并可靠使用手机能力”更真实、更简单或更可靠。
