# 13 安全与用户控制边界

## 1. 文档范围

本文只描述架构中已经需要存在的控制点和可配置边界，不替用户扩张限制，不预设复杂审批制度，也不把 MVP 变成权限平台。

原则是：

> 控制权持续归用户；强制策略只在产品明确决定后配置，不由实现方擅自扩大。

## 2. 必要控制点

### 2.1 统一入口

Web、Hermes 和微信都通过 Runtime Gateway。Client 不能直接访问 ADB、模型 Adapter 或 Event Store。

### 2.2 设备执行权

同一时刻只有 Runtime 可以为当前 Task 向目标设备发出自动 Action。设备与 Task 的绑定必须明确，避免命令落到错误设备。

### 2.3 用户生命周期控制

用户始终可以：

- 查看当前 Task 与 Stage；
- 暂停自动执行；
- 明确继续；
- 取消 Task；
- 手动接管设备；
- 发送新的目标、约束或补充信息。

### 2.4 结构化 Action 校验

模型输出不能直接执行。Runtime 校验 Action 类型、参数、Observation 版本、设备状态和 Task 状态后，才交给设备层。

### 2.5 Verify 后 Commit

只有基于新 Observation 验证成功的结果才能成为已确认进度，防止系统仅凭模型声明或命令返回码误报完成。

## 3. 可配置边界

部署方可以配置，但本文不替用户选择具体值：

- 可使用的 Android 设备；
- 允许的 Action 类型；
- 本地与云端模型是否可用；
- 哪类 Observation 可以发送给哪类模型实现；
- 超时、重试和无进度阈值；
- 事件、截图和日志的保留期限；
- 哪些 Client 可以创建或控制 Task；
- 是否允许 Hermes / 微信接入；
- 需要显式用户确认的动作类别（如未来产品决定需要）。

这些应通过可读配置表达，不散落为隐蔽硬编码。

## 4. 暂停、取消与接管语义

### 暂停

Runtime 停止产生新的自动 Action，保留 Task 状态。已发出但结果不确定的动作必须在恢复时先观察，不能直接重复。

### 取消

Task 进入终态 `CANCELLED`，不再执行动作。取消不会擅自清除事件和诊断证据。

### 手动接管

Runtime 进入 `PAUSED`，用户直接操作设备。恢复自动执行时必须重新观察和必要时重新规划。

## 5. 身份与会话关联

Gateway 必须能区分 Client、conversation、message 和 task，防止后续控制消息落到错误任务。具体认证方案属于部署决策；MVP 至少不能用不稳定的显示名称作为唯一关联键。

## 6. 数据可见性

主聊天只显示完成任务所需的信息；屏幕画面、UI Tree、模型调用和 ADB 日志放在展开详情。具体保留期限和访问策略可配置。

本基线不规定自动上传所有屏幕内容，也不规定必须禁止云端。Router 应尊重部署配置，并在调用元数据中记录实际 Binding。

## 7. 失败时的控制

- 设备未连接或状态未知时停止动作；
- Task 已暂停、取消或终结后拒绝动作；
- Action 结构不合法时拒绝执行；
- 重复无进度时进入恢复或请求用户，不无限点击；
- Gateway 的重复请求通过幂等机制去重。

## 8. 不在本文擅自增加的限制

本文不默认引入：每次点击审批、全局禁止云模型、复杂角色权限矩阵、所有动作白名单工作流、敏感页面识别系统、内容审查系统或企业级审计平台。

若产品以后需要这些能力，应由用户明确边界和预期效果，再形成新的设计与施工单。

## 9. MVP 验收

- 所有自动设备操作都可追溯到一个 Active Task；
- 暂停和接管后不会继续产生新 Action；
- 恢复后使用全新 Observation；
- Client 无法绕过 Gateway 直接调用 ADB；
- 模型输出在执行前经过结构化校验；
- 用户可见状态与 Runtime 实际状态一致。
