# 10 前端聊天工作台

## 1. 产品原则

> 聊天是主界面，其余一切均可展开查看。

前端不是 Agent 配置控制台，也不是终端日志瀑布。默认视图帮助用户提出目标、理解当前进度并持续控制任务。

## 2. v0.1 主界面

```text
┌─────────────────────────────────────────────┐
│ Soul                         Android Device ●│
├─────────────────────────────────────────────┤
│                                             │
│  你：打开设置，查看电池信息，然后回桌面。  │
│                                             │
│  Soul：已进入设置，正在查找电池页面。       │
│                                             │
│  当前阶段：进入电池信息页面                 │
│  状态：运行中                               │
│                                             │
│              [ 查看执行详情 ▾ ]             │
│                                             │
├─────────────────────────────────────────────┤
│  告诉 Soul 你想做什么……      [发送]        │
└─────────────────────────────────────────────┘
```

主界面最小元素：

- 聊天消息流；
- 消息输入；
- 设备连接指示；
- 当前 Task 状态；
- 当前 Stage 简述；
- 展开执行详情；
- 暂停、继续、取消、手动接管的可达入口。

## 3. 展开式执行详情

第一阶段展示：

- Current Stage；
- Phone Screen；
- Recent Actions；
- Runtime State；
- 当前 Planner / Operator / Language Binding；
- Event Log；
- ADB Log（更深一层展开）。

工程信息默认折叠。展开详情的目的是理解行为和诊断失败，不要求普通用户理解所有字段。

## 4. 消息语义

用户在 Task 运行中发送的消息可能是：

- 新约束：“不要继续进入其他页面”；
- 目标修正：“读取完就直接回桌面”；
- 附加信息：“设置图标在第二屏”；
- 暂停：“先停一下”；
- 继续：“现在继续”；
- 取消：“不用做了”；
- 手动接管：“我自己操作”。

前端只发送原始消息和明确控件意图；最终分类由 Runtime 完成，并通过事件回显解释。

## 5. 任务状态呈现

建议将内部状态映射为清晰文字：

| Runtime 状态 | 主界面呈现 |
|---|---|
| `CREATED` / `PLANNING` | 正在理解任务 |
| `RUNNING` | 正在执行 |
| `WAITING` | 等待条件或需要你的信息 |
| `PAUSED` | 已暂停 |
| `STUCK` | 暂时无法继续 |
| `COMPLETED` | 已完成 |
| `FAILED` | 执行失败 |
| `CANCELLED` | 已取消 |

主界面不以 `running=true` 之类技术字段代替实际进度。

## 6. 实时更新

前端通过 Gateway 事件流更新：

- 状态变化；
- Stage 变化；
- 用户可读进度消息；
- 新 Observation 预览；
- Action / Verify 摘要；
- 完成、失败或等待请求。

断线重连时使用事件 sequence 续传，并重新拉取 Task Snapshot 校准界面。

## 7. 设备画面

Phone Screen 展示最近有效 Observation。应明确画面采集时间；设备断开或画面过期时显示状态，不把旧图伪装为实时画面。

MVP 不要求在浏览器中直接远程触控手机。所有自动设备动作仍由 Task Runtime 经过 Operator 和 Action Executor 发出。

## 8. 手动接管

用户选择手动接管时：

1. 前端向 Gateway 发送接管命令；
2. Runtime 进入 `PAUSED`；
3. 不再发出自动 Action；
4. 界面明确显示“已由你接管”；
5. 用户选择继续后，Runtime 先重新观察设备再规划，不能沿用接管前的旧画面。

## 9. MVP 不做的界面

不建设 Agent 管理、Prompt 编辑器、复杂模型市场、Token Dashboard、Memory 管理台、Skill 商店、多设备调度台或完整移动端应用。模型与运行参数只保留开发所需的最低配置入口，不抢占聊天主界面。

## 10. 前端验收重点

- 用户能从聊天创建 MVP Task；
- 运行中能看到当前 Stage 与真实状态；
- 展开后能看到与 Runtime 事件一致的设备画面和动作摘要；
- 暂停、继续、取消、接管通过 Gateway 生效；
- 页面关闭不导致后端 Task 自动终止；
- 重新打开页面可以恢复展示同一 Task 的当前状态。
