# Gameplay readiness boundary

本文定义 AI-GAME 从当前 Android 离散 GUI 自动化走向“类王者荣耀简单游玩”的未来验收线。这里的“类王者荣耀”只描述双摇杆/技能按钮式移动战斗交互，不表示已适配、已认证或已通过任何具体商业游戏。

> 当前结论：尚未达到游戏实时控制就绪。现有实现可以在“截图 → 一个动作 → 动作后截图”的无固定步数、串行闭环里导航普通 Android 页面，但没有高频本地控制、多点触控、连续视觉状态估计或 3–5 分钟游戏耐久证据。以下目标架构和验收项都是未来要求，不是当前能力声明。

> 新增的有界 `LearningEpisode` 只为 G0 低频离散闭环补充 Transition ledger、本机证据、OutcomeVerifier、RewardSignal 和版本化轨迹蒸馏；它不满足 G1–G4，不训练权重，也不能把 `stzb-tutorial-v1` 外推成“已经会玩率土之滨”。

已有一条任务级实际 Android 运行证据：MobileTask
`daac81a7-1af9-47e3-9566-66e73509a0fd` 在 23 次 ActionAttempt 后完成，
自动 SkillMemory scope 为 `auto:stzb/tutorial/v1`，本机证据包括
`runtime/sessions/mobile-tasks/evidence/ec5f551bfb124b0d8739a16fcba76fac.png`。
这只证明该 MobileTask 的完成事实，不证明 GameLearning Episode/PolicyMemory、
通用率土能力或任何 G1–G4 实时控制 gate 已通过。

## 允许范围

验收只允许在用户拥有并明确选择的训练模式、自定义房间、离线测试地图或专用 QA 沙盒中进行，并使用固定的测试账号、角色、分辨率、按键布局和地图版本。测试开始点应已完成登录，并预先排除凭据、验证码/生物识别、实名/身份核验、付款、CAPTCHA、系统权限或法律确认页面。当前测试模式不会因为这些页面内容自动暂停；若测试越出预定场景，操作者必须主动停止，并把该运行判为范围越界失败。

以下内容不在本验收范围内：排位、公开匹配、与不知情真人玩家对战、代练或刷取账号收益、购买/充值、规避反作弊、修改游戏进程或网络流量，以及把训练场通过外推成真实竞技能力。

## 当前基线：离散截图—动作闭环

当前一级游戏路径是 MobileTaskRuntime。它持久化 TaskState、TaskPlan 和
Subgoal，接受任务中途 Input，并顺序调用同一个本地 GUI-Owl-compatible
endpoint 承担 Planner、Executor、BEFORE 摘要、AFTER 摘要、Verifier 和
Reflection。每个物理 intent 在下发前先持久化，最多调用一次 Windows ADB
Adapter；随后取得新鲜 AFTER 画面并验证可见后置条件。MobileTask 不调用
云端聊天模型，也不把原始设备截图上传到云端。

当前可解析和传输的动作包括单点点击、长按、单指滑动、受限文本输入和
系统按键，以及不产生设备输入的等待、重定向与结束。任务可绑定动态发现的
模拟器、USB 或无线 Android Target；安全检查点可在重启后恢复，但持久化且
未收口的物理 intent 必须进入 `uncertain / restart_open_intent`，不得重放。
用户 Input 或 Stop 会阻止后续新动作，但无法撤回 ADB 已接收的原子输入。
自动 SkillMemory 也只有在新鲜证据确认目标后才可能晋升。

兼容 `cloud_execute` Chat 模式仍存在，但它不是当前游戏能力的主事实来源。
无论从哪个低频入口执行，ADB 接收动作都不能替代应用级结果验证。

这条链路适合菜单导航和低频应用操作，但不能据此宣称已经会玩实时游戏，原因包括：

- 每个物理动作前都要重新截图并等待一次本地模型决策，没有持续帧流、显式帧时钟或稳定控制周期；
- 当前手势是顺序、单指、一次一个动作，没有可保持的 pointer 生命周期，也不能同时维持摇杆并点击普攻或技能；
- 没有面向角色位置、朝向、目标、技能冷却、血量、回城状态等游戏语义的连续状态估计；
- 没有独立于云端/GUI 推理延迟的高频本地控制器；
- 现有时间线能区分观察、提议、ADB 已接收和动作后观察，但还不是完整的帧、控制延迟、命中后置条件与 watchdog 遥测；
- 没有连续 3–5 分钟无人干预运行、技能组合、撤退/回城或故障恢复的实机验收证据。

`transported` 只表示 ADB 接受了输入，不表示角色移动、攻击命中、技能释放或场景目标已经完成；未来验收也必须保留这条事实边界。

## 当前两条低频游戏证据路径

MobileTask 面向通用长期目标：它使用持久 TaskPlan/Subgoal、Reflection 和
自动 `auto:stzb/*` SkillMemory scope，并允许任务中途 Input。GameLearning
则是保留的高级/实验性 Interface：每个 Job 只运行一个有最大动作数和最大
时长的低频 `LearningEpisode`，使用独立的 `stzb-tutorial-v1` Profile 和
PolicyMemory。两者的数据库、状态机和验收结果互不替代。

这两条路径都会按序记录或保存观察、提议、传输、动作后观察和验证事实，
但都没有持续帧流、20 Hz 控制时钟、pointer 生命周期、多点触控或 realtime
watchdog。因此它们都只属于 G0 低频证据基础设施，不是 G1 实时基础设施。

任何“学习”状态都不能替代 gameplay gate：MobileTask `completed`、Episode
结束、`result=learned`、PolicyMemory 晋升和 `transport accepted` 是不同
事实。首版 GameLearning 没有持久化 PolicyCandidate；只有已确认成功且含
正奖励物理 Transition 的轨迹才会原子蒸馏并晋升新 PolicyMemory 版本。
未来若加入显式 PolicyCandidate，候选存在仍不等于已晋升。任一种任务级
记忆也不证明任意地图、角色、账号、赛季或真人竞争能力。

`stzb-tutorial-v1` 只允许固定、已授权、已登录起点中的教程推进，以及任务、武将、部队、地图等只读菜单导航和返回主界面；领取、招募、强化、出征、聊天/联盟、真人交互、公开竞争、登录/账号、验证码、实名和支付等均不在范围内。详细边界见 [`game-learning.md`](game-learning.md)。范围外、低置信度或无法验证的证据必须得到 `unconfirmed`、失败或停止结果，不能自动生成正奖励或晋升 PolicyMemory。

进程关闭或重启后，MobileTask 和 GameLearning 都不会重放未确认的物理
动作；物理状态无法确认时必须保留不确定结论。未来若增加离线
`TrainingJob` 或 LoRA Adapter，它们仍需独立的数据冻结、授权、训练、
评估、激活和实机 gate，不能由 LearningEpisode 自动触发。

## 目标架构

游戏控制不能把“每个输入都等待一次云端或 GUI 模型调用”放在实时路径上。目标分层如下：

```text
低频云端 / 本地 GUI 规划（场景目标、宏观意图、恢复策略）
                    |
                    v
本地视觉状态估计（带时间戳、置信度和新鲜度的结构化状态）
                    |
                    v
高频本地控制（短时轨迹、摇杆保持、技能时序、目标锁定）
                    |
                    v
多点触控传输（pointer down / move / up、原子批次、release-all）
                    |
                    v
            Android 训练 / 自定义 / 沙盒

watchdog 监视帧、规划、控制、传输和用户取消，并可使输入回到中立状态
遥测总线记录规划、状态、动作、延迟、后置条件和失败，不把传输当成结果
```

### 低频云端 / GUI 规划

云端或本地 GUI 模型只负责低频决策，例如“进入训练场”“接近指定木桩”“撤退并回城”，并产生带版本和期限的宏观意图。云端只接收对话与经过约束的结构化状态摘要；当前“不上传原始截图”的边界不因游戏控制而自动改变。规划超时不能冻结正在执行的安全本地控制；旧意图到期后必须降级为停止、撤退或释放全部触点。

### 本地视觉状态估计

本地估计器从连续采集的画面生成带 `frame_id`、采集时间、帧龄和置信度的状态：当前场景（启动页/大厅/训练场/战斗/结算）、角色与可移动区域、移动方向、候选目标、普攻与三个技能的可用/冷却状态、血量或危险代理、回城通道和遮挡/弹窗。低置信度、陈旧帧或未知场景必须显式上报，不能沿用过期坐标盲点。

### 高频本地控制

本地控制器把宏观意图和最新状态变成短时、可撤销的输入计划。摇杆保持、转向、攻击与技能时序在本机控制周期内完成，不能以云端往返作为每次输入的前置条件。所有计划都有截止时间；新状态、用户停止或 watchdog 触发时可抢占，并在退出路径释放所有触点。

### 多点触控传输

传输层需要稳定的 pointer 标识和明确的 `down`、`move`、`up` 生命周期，支持至少“左侧摇杆持续按住 + 右侧普攻/技能点按”的两个并发触点。批次的排序、时间戳、目标设备绑定和确认语义必须确定；重连后不得重放状态不明的 `down` 或技能点击。任何取消、超时、异常和进程退出都必须执行幂等 `release-all` 或等价的设备中立化。

### Watchdog

watchdog 独立监视画面停滞、帧龄、估计置信度、控制周期 deadline miss、ADB 断连、触点保持时长、宏观意图过期、无进展循环、场景跳变和用户停止。这些属于未来设备、状态估计或控制异常检测，不是按凭据、付款、权限、协议、CAPTCHA 等页面语义设置的 hard-stop。触发后先阻止新输入，再释放触点并记录原因；传输已不可靠时不得假定释放成功，必须把状态标为不确定并要求人工检查。任何不确定物理动作都不得自动重发。

## 固定验收环境

每次正式验收应记录设备/模拟器版本、ADB 目标、屏幕分辨率和方向、游戏/沙盒版本、地图、角色、技能和按键布局、帧采集方式、模型与控制器版本以及本地/云端配置修订。开始画面必须是已登录且无敏感提示的固定启动页；开始后除紧急停止外不得有人工输入。

正式结论至少需要三次连续、可复现的独立运行。只通过录屏观察、单次演示、静态截图、单元测试或 ADB 返回码，都不能替代端到端实机证据。

## 未来功能验收线

| 能力 | 最小场景 | 通过条件 | 必要证据 |
| --- | --- | --- | --- |
| 进入大厅与训练场 | 从固定、已登录的安全启动页开始 | 依次识别并到达大厅、指定训练/自定义/沙盒地图；每个场景均由新画面状态确认，而不是按点击次数推断 | 场景状态序列、关键帧引用/哈希、规划与导航动作、超时/恢复记录 |
| 持续移动 | 训练地图内直行、转向和停止 | 摇杆连续保持至少 10 秒，完成至少三次方向改变；角色运动与停止均被视觉状态确认；结束后无残留触点 | pointer 生命周期、控制周期统计、轨迹/位移估计、release-all 结果 |
| 目标选择 | 多个合法训练目标同时可见 | 选择指定木桩、机器人或沙盒目标，维持目标身份直到攻击窗口；不误触队友、商店、设置或离开场景控件 | 候选目标、置信度、选择理由、目标锁定/丢失事件 |
| 普攻 | 指定目标进入攻击范围 | 发出十次可执行普攻时，至少九次由画面后置条件确认；ADB 接收但无攻击反馈计为失败，不得计入成功 | 每次动作的意图、传输、后置条件、命中/未确认分类及延迟 |
| 三个技能 | 三个技能均可用的固定角色 | 技能 1、2、3 分别成功释放并观察到冷却或效果；至少一次在持续移动时释放，以证明多点触控而非串行假动作 | 技能可用状态、pointer 并发区间、释放与效果/冷却确认、失败原因 |
| 撤退与回城 | 预设危险或低血量代理条件 | 触发撤退，移动到预设安全区域，开始并保持回城；若回城被合法中断，能识别中断并按有界策略重试或停止 | 触发条件、撤退轨迹、回城通道状态、重试预算与最终状态 |
| 连续运行 | 上述能力组成一个闭环 | 每次无人干预持续 3–5 分钟，至少包含进训练场、移动、选目标、普攻、三个技能、撤退/回城；无进程崩溃、未知残留触点、越界场景或未记录失败；连续三次通过 | 完整运行清单、视频或关键帧证据、遥测摘要、watchdog 与最终中立状态 |

功能项必须由观察到的后置条件判定。若状态估计无法可靠确认，结果应为 `unconfirmed` 或失败，而不是自动补成成功。

## 性能与安全验收线

以下是首版目标门槛；实现开始后可以用基准测试收紧，但任何变更都应版本化并写入验收报告，不能为了让失败运行变绿而静默放宽。

- 高频本地控制周期至少 20 Hz，活跃控制阶段 deadline miss 少于 1%；云端或 GUI 规划暂停时，本地安全控制和 watchdog 仍继续运行。
- 用于控制的视觉状态帧龄 p95 不高于 250 ms、p99 不高于 500 ms；超过上限的状态不得驱动新的攻击或技能动作。
- 从本地控制器计划时间到多点触控传输接受时间，p95 不高于 75 ms、p99 不高于 150 ms；应用画面响应延迟另行记录，不能混入传输延迟。
- 连续 3–5 分钟运行中，所有 `down` 都必须恰好有一个可追踪的 `up` 或最终 `release-all`；未知触点数量必须为零。
- watchdog 应在心跳丢失、陈旧画面、ADB 断连或用户停止后的 500 ms 内停止调度新输入，并在传输仍可用时于额外 500 ms 内发出中立化操作。
- 未知场景或状态置信度低于已冻结阈值时，应作为视觉/控制异常中立化并结束验收运行；购买、公开匹配、账号或系统授权流程属于验收范围越界，而不是依赖当前页面分类器自动拦截。

## 动作、延迟与失败遥测

每次运行需要一个不可混淆的 `gameplay_session_id` 和单调时钟；这个标识
不是兼容控制面的 legacy Run resource。遥测至少覆盖：

- 规划：`intent_id`、规划器类型与版本、输入状态修订、创建/到期时间、规划延迟、替换或取消原因；
- 画面与状态：`frame_id` 或本机证据引用/哈希、采集时间、帧龄、估计完成时间、场景、关键状态、置信度和低置信度原因；
- 控制：`action_id`、计划时间、截止时间、动作类型、目标、pointer 标识与阶段、坐标/轨迹、控制周期和 deadline miss；
- 传输：发送、接受和完成/不确定时间，队列延迟、传输延迟、ADB 目标身份、返回分类和重试次数；
- 后置条件：观察时间、预期与实际状态、确认延迟，以及 `confirmed`、`unconfirmed` 或 `failed`；
- 故障：稳定错误码、首次发生点、影响范围、是否停止新输入、是否完成 `release-all`、watchdog 触发原因和人工接管状态。

至少区分 `frame_stale`、`scene_unknown`、`state_low_confidence`、`planner_timeout`、`control_deadline_miss`、`transport_disconnected`、`transport_uncertain`、`postcondition_not_observed`、`no_progress`、`pointer_release_unconfirmed`、`scope_boundary_violation` 和 `user_cancelled`。`scope_boundary_violation` 是验收证据分类，不表示当前聊天循环具有敏感页面 hard-stop。日志不得包含 API key、凭据、必须原样输入的敏感文本或原始模型响应；截图证据按本机保留策略保存，只在 SQLite/事件中记录哈希和相对引用。

正式报告应分别给出功能通过率、动作确认率、各段 p50/p95/p99 延迟、deadline miss、状态低置信度占比、失败码分布、watchdog 次数和触点配平结果。代码存在、测试通过、传输成功、画面变化和整个场景验收是五种不同证据，不能互相替代。
